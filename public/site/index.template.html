What this page is for. It is served from http://localhost:5500 while the API runs on http://localhost:3000 — a different port, and therefore a different origin. Every request the widget makes from this page is cross-origin, which is the whole point: it exercises CORS, preflight, and the public submission endpoint exactly the way a real customer's site would.

The one line that does it

This is the entire integration — the snippet the API handed the owner:

<script src="http://localhost:3000/widget.js?id=REPLACE_WITH_PUBLIC_ID" async></script>

Open the network tab and watch the sequence: the loader arrives with a short cache, it pulls the versioned bundle (cached for a year, because its URL contains a hash of its own contents), the bundle fetches the widget's config, and submitting fires a preflight OPTIONS before the real POST.

Not a real coffee company. Run npm run seed to get a widget id, then paste it into the two REPLACE_WITH_PUBLIC_ID spots above — or let the seed script write them for you.
